# Выкладка на reg.ru — чек-лист владельца

Сайт и админка выкладываются из GitHub Actions (`.github/workflows/deploy-regru.yml`) по FTPS при каждом push в `main`
(и вручную: Actions → «Deploy to reg.ru hosting» → Run workflow). SSH на хостинге не нужен.

Что делает выкладка:

1. Собирает приложение (`composer install --no-dev`, `npm run build` под `https://matuzov.ru`) и проверяет шаблоны.
2. Загружает приложение в папку **вне** `www` (`REGRU_APP_PATH`). Если там ещё нет `.env`, создаёт его
   из `deploy/regru/env.template` с новым `APP_KEY`. Существующий `.env` не трогается никогда.
3. Кладёт в папку сайта только ресурсы: `build/`, `brand/`, `app.php`, `.htaccess`, `.user.ini`, `favicon.ico`,
   `site.webmanifest`. HTML-страницы, `media/` и ресурсы Filament пишет само приложение.
4. Вызывает хук `POST https://matuzov.ru/_deploy/<DEPLOY_TOKEN>`: база → миграции → перенос наполнения (один раз) →
   первый администратор (если пользователей нет) → ресурсы Filament → публикация сайта → кеши.

Защита: если папка похожа на корень хостинга — стоп; удаляются лишние файлы только в папках с метками
`.matuzov-app` / `.matuzov-deploy`; в непустую папку без метки приложение не кладётся.

## Перед первой выкладкой

1. **Резервная копия хостинга** в панели reg.ru (ISPmanager → «Резервные копии»), прежде чем что-либо запускать.
2. **PHP 8.3** для сайта matuzov.ru (ISPmanager → «Сайты» → matuzov.ru → «PHP»), режим CGI/FastCGI/PHP-FPM.
   Расширения: `intl`, `zip`, `gd`, `pdo_sqlite`, `fileinfo`, `mbstring` (ISPmanager → «PHP» → «Расширения»).
3. **«Перенаправлять на HTTPS»** включено для сайта (в `.htaccess` переадресации на https нет — её делает nginx).
4. **Абсолютные пути.** В ISPmanager → «Сайты» → matuzov.ru видна корневая папка сайта, например
   `/var/www/u1234567/data/www/matuzov.ru`. Домашняя папка — часть до `/www/…` (`/var/www/u1234567/data`);
   корень FTP — она же. Папка приложения: `/var/www/u1234567/data/matuzov-app` (создавать заранее не нужно).
5. **Секреты** (GitHub → Settings → Secrets and variables → Actions → Secrets):

   | Секрет | Пример / что это |
   |---|---|
   | `REGRU_HOST` | `server123.hosting.reg.ru` |
   | `REGRU_USER` | `u1234567` |
   | `REGRU_PASSWORD` | пароль FTP |
   | `REGRU_PATH` | `www/matuzov.ru` |
   | `REGRU_SITE_ABS_PATH` | `/var/www/u1234567/data/www/matuzov.ru` |
   | `REGRU_APP_PATH` | `matuzov-app` |
   | `REGRU_APP_ABS_PATH` | `/var/www/u1234567/data/matuzov-app` |
   | `DEPLOY_TOKEN` | случайная строка от 32 символов: латиница, цифры, `-`, `_` (например вывод `openssl rand -hex 32`) |
   | `ADMIN_PASSWORD` | пароль входа в админку, от 10 символов (вход — только по паролю) |
   | `ADMIN_EMAIL` | необязательно: внутренний адрес администратора (по умолчанию `admin@matuzov.ru`) |

   Переменная (Variables): `REGRU_DEPLOY` = `ftp`.
   Абсолютные пути должны заканчиваться относительными (`…/www/matuzov.ru` ↔ `www/matuzov.ru`) — workflow это проверяет.
6. **Адрес nginx → PHP.** Лимит заявок КП считает реальный IP посетителя из `X-Forwarded-For`, но доверяет ему
   только от частных адресов (`TrustProxies` в `bootstrap/app.php`: 127.0.0.1, 10/8, 172.16/12, 192.168/16).
   После выкладки проверьте в `storage/logs` или временным `phpinfo()`, что `REMOTE_ADDR` у запросов — частный
   адрес. Если нет — лимит будет общим для всех посетителей; напишите разработчику.

## Если что-то пошло не так

- **Шаг «Check secrets» красный** — в тексте ошибки сказано, какой секрет заполнен неверно (значения не печатаются).
- **«похожа на корень хостинга»** — в `REGRU_PATH`/`REGRU_APP_PATH` указан корень; ничего не загружено.
- **Хук ответил 404** — `DEPLOY_TOKEN` в секрете и в `.env` на сервере различаются (после первой выкладки токен
  живёт в `~/matuzov-app/.env`; меняете секрет — поменяйте и там), или `.htaccess` в папке сайта старый.
- **Хук ответил 500** — в логе шага видно, на каком шаге (`migrate`, `import`, `publish`…) и с какой ошибкой.
  Подробности — `~/matuzov-app/storage/logs/laravel-*.log` (файловый менеджер панели). Исправить и запустить
  workflow ещё раз: все шаги повторяемы, наполнение переносится только в пустую базу, админ — только если
  пользователей нет.
- **423 / таймаут** — первая установка (нарезка фото) идёт дольше таймаута хостинга; workflow ждёт и повторяет
  сам (до ~10 минут). Если так и не дождался — подождите пару минут и перезапустите.
- **Сайт сломан, нужно откатиться** — восстановить резервную копию в панели; `~/matuzov-app/database/database.sqlite`
  и `.env` — главное, что нельзя потерять (база с правками из админки и ключ шифрования).
