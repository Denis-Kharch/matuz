# Админка (этап 3): план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Админка Filament на `matuzov.ru/admin`. В ней редактируется всё наполнение сайта, включая фото с кадрированием. Хранение — SQLite. После каждого сохранения публичный статичный сайт пересобирается за секунды. Заявки КП сохраняются и уходят в Telegram. Выкладка — по push через FTPS, без SSH.

**Architecture:**
- Laravel-приложение лежит на хостинге вне веб-папки (`~/matuzov-app`). Его `public_path` переопределён на папку сайта (`~/www/matuzov.ru`).
- Входной файл `app.php` в папке сайта запускает Laravel только для `/admin`, `/livewire`, `/api/kp-lead` и `/_deploy`. Остальное Apache отдаёт как статичные файлы.
- Наполнение читается через тот же интерфейс `ContentRepository`, теперь из базы (`DatabaseContentRepository`).
- `SitePublisher` пишет HTML-страницы в папку сайта атомарно, по файлу. Фото нарезаются при сохранении сразу в `media/` папки сайта.

**Tech Stack:** Laravel 13, PHP 8.3, SQLite, Filament ^5.11 (Livewire), intervention/image ^3 (GD), symfony/html-sanitizer, cropperjs ^1.6 (редактор кадра в админке), Pest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-09-admin-design.md`. Опирается на `docs/superpowers/specs/2026-11-06-matuzov-site-design.md` (§7 КП).

## Global Constraints

- **Структура страницы фиксированная.** Добавляются, удаляются, скрываются и переставляются только элементы внутри существующих блоков. Конструктора разделов нет.
- **Пользователи админки равны.** Ролей нет, истории изменений нет. Вход по e-mail и паролю.
- **Админка на русском**, путь `/admin`. Приоритет — работа с компьютера.
- **База — SQLite**, файл `database/database.sqlite` в папке приложения. MySQL не используется.
- **На хостинге нет SSH и фоновых процессов.** Все серверные действия выполняются HTTP-запросами (защищённый хук деплоя) или после ответа браузеру (`afterResponse`).
- **Публичный сайт остаётся статичным.**
  - Ошибка пересборки не меняет ни одного файла публичного сайта.
  - Удаляются только страницы, которые пересборка сама создавала.
  - `media/` и ассеты пересборка не трогает.
- **Длинные тексты (rich).** Разрешены только `p, br, strong, b, em, i, a[href], ul, ol, li`. Без шрифтов, цветов и размеров. На сайте HTML очищается.
  - Поля: абзацы «Об Андрее», ответ FAQ, запрос, результат и отзыв кейса, описание события.
- **Пропорции кадрирования** (из спецификации, §6.1):
  - первый экран — 16:9 + фокус, вертикальное фото для телефона 9:16;
  - «Об Андрее» — 4:5;
  - этап опыта — 16:10;
  - кейс: обложка 16:10 + фокус, фото 4:3;
  - событие — 4:3 + фокус;
  - галерея — свободно;
  - регалия — 16:10;
  - партнёр — без кадрирования.
- **Фото:**
  - JPG, PNG, WebP, HEIC (если GD умеет), до 15 МБ;
  - пачкой до 30 (галерея, события);
  - ширины версий 640/1280/1920 (не больше кадра), webp q72, avif q50 (если `imageavif` есть, иначе только webp);
  - оригинал хранится, кадр можно переделать.
- **Заявки КП:**
  - поля: компания (обязательно, ≤ 200), город (≤ 100), источник (≤ 50);
  - защита: honeypot `website`; не больше 5 заявок в минуту с одного IP;
  - сбой Telegram не мешает ни сохранению, ни посетителю.
- **Выкладка** — FTPS. Никогда не перезаписываются и не удаляются: `.env`, `storage/`, `database/database.sqlite`, `media/`, HTML-страницы сайта. Защита «корень хостинга → стоп» сохраняется.
- **Коммиты** заканчиваются строкой `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Окружение на Windows:** npm/node запускаются с `NODE_OPTIONS="--dns-result-order=ipv4first --no-network-family-autoselection"`; Playwright использует порт 4710.

## Review Focus

1. **Два быстрых сохранения подряд или сохранение во время пересборки.** Ни одно изменение не теряется: вторая пересборка запускается после первой; на сайте окажется последнее состояние. Тест — Task 6.
2. **Удалили кейс, у которого была страница.** Страница `cases/<slug>/` исчезает, адрес отдаёт 404. Остальные страницы, `media/` и `build/` целы. Тест — Task 6.
3. **Поменяли slug кейса или события.** Старая страница удаляется, новая появляется, ссылки на главной ведут на новую. Тест — Task 6.
4. **В rich-поле вставлен HTML из Word или опасный код** (`<script>`, `onclick`, `style`, `<font>`). На сайте остаются только разрешённые теги, текст не теряется. Тест — Task 5.
5. **Загружено огромное фото (6000 px, 15 МБ) или фото с поворотом в EXIF.** Обработка укладывается в лимит памяти: версии не больше 1920 px, ориентация верная. Тест — Task 3.

### Task 3: Фото — модель Media и обработка

**Files:**
- Create: миграция `media`, `app/Models/Media.php`, `app/Models/Concerns/HasMedia.php`, `app/Media/MediaProcessor.php`, `app/Media/CropSpec.php`
- Modify: `app/Support/ImageManifest.php`, `resources/views/components/picture.blade.php`
- Test: `tests/Feature/MediaProcessorTest.php`, `tests/Feature/ComponentsTest.php` (дополнить)

**Interfaces:**
- Produces:
  - **таблица `media`:**
    - `owner_type`, `owner_id` (morph; null для одиночных блоков настроек, тогда `slot`), `collection`;
    - `original_path` (диск `local`, `media-originals/…`);
    - `crop` json `{x, y, width, height, rotate, flipX, flipY}` в пикселях оригинала или null = весь кадр;
    - `focal_x`, `focal_y` 0–100 (default 50/50);
    - `alt`, `caption`, `sort`;
    - `key` (уникальная строка `media/{id}-{hash8}`, меняется при каждой новой нарезке);
    - `widths` json, `formats` json, `width`, `height` (кадра);
  - `HasMedia` — `media(string $collection): MorphMany` (упорядочено по `sort`) и `firstMedia(string $collection): ?Media`;
  - `MediaProcessor::process(Media $m): void`:
    - читает оригинал, применяет ориентацию из EXIF, поворот и отражение, затем кадр;
    - ресайз под каждую ширину `[640, 1280, 1920]`, которая ≤ ширины кадра. Если кадр уже, чем 640, берётся его собственная ширина;
    - пишет `{public_path}/{key}-{w}.webp` и `.avif` (avif — только если `function_exists('imageavif')`);
    - удаляет файлы прежнего `key`, обновляет `key`, `widths`, `formats`, `width`, `height`;
  - `Media::booted`: на `saved`, если изменились `original_path` или `crop`, вызывается `process`; на `deleted` удаляются файлы и оригинал;
  - `ImageManifest::get(string $key): array{base:string, widths:list<int>, width:int, height:int, formats:list<string>, focal:?array{x:int,y:int}}`:
    - ключ `media/…` берётся из таблицы `media`, `base = $key`;
    - иначе берётся из `public/img/manifest.json`, `base = "img/{$key}"`, formats `['avif','webp']`;
  - `<x-picture>` строит srcset из `base`/`formats`/`widths`. Если `focal` не передан, берётся из манифеста.

    $m->refresh();
    expect($m->width)->toBe(1600)->and($m->height)->toBe(1000)->and($m->widths)->toBe([640, 1280])
        ->and(is_file(public_path($m->key.'-1280.webp')))->toBeTrue();
    expect(getimagesize(public_path($m->key.'-640.webp'))[1])->toBe(400);
});
it('writes avif only when GD supports it', fn () => expect(in_array('avif', Media::factoryCover()->formats))->toBe(function_exists('imageavif')));
it('re-crop replaces files and key', function () {
    $m = Media::factoryCover(); $old = $m->key;
    $m->update(['crop' => [...$m->crop, 'width' => 800, 'height' => 500]]);
    expect($m->fresh()->key)->not->toBe($old)->and(glob(public_path($old.'-*')))->toBe([]);

});
it('handles a 6000px original within 1920 output', function () {
    $m = Media::create(['collection' => 'x', 'original_path' => $this->store('6000x4000.jpg')]);
    expect(max($m->fresh()->widths))->toBe(1920);
});
it('deleting media removes its files', function () {

    expect(glob(public_path($key.'-*')))->toBe([]);
});
it('manifest serves media entries with focal', function () {

### Task 6: Пересборка и публикация сайта

**Files:**
- Create: `app/Site/SiteBuilder.php`, `app/Site/SitePublisher.php`, `app/Console/Commands/PublishSite.php`
- Modify: `app/Console/Commands/ExportSite.php` (рендер через `SiteBuilder`), привязка `PublishQueue` → `SitePublisher`

**Interfaces:**
- Consumes: маршруты сайта, `ContentRepository`.
- Produces:
  - `SiteBuilder::paths(): list<string>` — тот же список, что раньше в `ExportSite::paths`;
  - `SiteBuilder::render(): array<string relativeFile, string contents>`:
    - каждый путь — через HTTP-ядро с `URL::forceRootUrl(config('app.url'))`;
    - ответ не 200 → `RuntimeException`;
  - `SitePublisher::publish(): PublishResult{ok:bool, at:CarbonImmutable, error:?string, pages:int}`:
    1. `render()`;
    2. проверка: есть `index.html`, `404.html`, `sitemap.xml`; в HTML нет `127.0.0.1` и `localhost`;
    3. каждый файл пишется в `{public_path}/{file}.tmp-{rand}` и переименовывается поверх;
    4. файлы из прошлого `{public_path}/.matuzov-pages.json`, которых нет в новом наборе, удаляются (только они);
    5. пишется новый `.matuzov-pages.json`;
    6. результат сохраняется в `Setting('publish_status')`;
  - при исключении на шаге 1 или 2 — ни одного изменения файлов, `ok=false`;
  - `SitePublisher implements PublishQueue`:
    - `request()` планирует `publish` через `dispatch(fn)->afterResponse()`, не чаще одного раза за запрос;
    - в консоли и тестах выполняет сразу;
  - блокировка: `Cache::lock('site-publish', 120)`. Если занята — ставится флаг `site-publish:again`, и держатель блокировки после публикации повторяет её, пока флаг поднят;
  - `SitePublisher::publishNow(): ?PublishResult` — взять блокировку и публиковать (повторяя, пока поднят флаг `site-publish:again`), либо, если блокировка занята, поднять флаг и вернуть null. Его вызывают `request()`, кнопка «Пересобрать сайт», хук деплоя и `site:publish`;
  - `php artisan site:publish` — синхронная публикация через `publishNow()`, выводит результат.
