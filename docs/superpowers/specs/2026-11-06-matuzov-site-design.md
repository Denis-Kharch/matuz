# Сайт Андрея Матузова — дизайн-документ

Дата: 2026-11-06
Источники: ТЗ заказчика (в переписке), его черновой HTML `Сайт Матузов.html`, палитра `b06f572b-…jpg`, черновые фото `exec-*.png`, референсы https://ui.watermelon.sh/ (blocks/hero, blocks/faq, blocks/blog).

## 1. Зачем и для кого

Андрей Матузов — бизнес-тренер, T&D-консультант и спикер из Санкт-Петербурга. Его заказчики — компании (B2B): HR, T&D, руководители и организаторы корпоративных событий.

У сайта одна главная цель: довести посетителя до **«моментального КП»**. Человек вводит только название компании (и, по желанию, город) и сразу получает персональное коммерческое предложение с возможностью скачать PDF. Телефон и персональные данные мы не просим — это принципиальная позиция, и сайт её прямо проговаривает.

Сайт должен выглядеть **премиально**: уровень дорогого личного бренда, а не шаблон.

Откуда пойдёт трафик, пока неизвестно. Исходим из того, что Андрей в основном сам присылает ссылку после знакомства или выступления. Поэтому приоритеты — первое впечатление, скорость на телефоне и базовое SEO под Яндекс. Структура должна позволять позже добавить посадочные страницы под темы тренингов.

## 2. Цели, не-цели, анти-цели

**Цели**
- Премиальная тёмная одностраничная витрина со всеми блоками из ТЗ (раздел 6).
- Моментальное КП: компания (+ город) → персональное КП на экране → PDF.
- Каждый запрос КП приходит Андрею в Telegram и сохраняется в админке (этап 3).
- Всё наполнение редактируется в админке без программиста (этап 3).

**Не-цели (сейчас)**
- Онлайн-оплата, личные кабинеты, многоязычность.
- Блок «Отзывы и рекомендации» из чернового HTML: его нет в ТЗ, отзывы живут внутри кейсов.
- SEO-посадочные страницы под отдельные темы — возможно, позже.
- Конструктор страниц: структура фиксированная, редактируется только наполнение.

**Анти-цели (провал, даже если всё работает)**
- Сайт выглядит шаблонно, «как Тильда» или «сделано ИИ».
- Форма просит телефон, e-mail или иные персональные данные.
- Кнопки КП навязчивые. В ТЗ сказано: «не противная кнопка».
- На телефоне сайт тяжёлый и медленный.

## 3. Ограничения

- **Хостинг:** reg.ru, обычный PHP-хостинг с MySQL. Всё (домен, хостинг, база) оформляется на заказчика.
  - Нужен тариф с PHP 8.3+, SSH и возможностью направить корень сайта в `public/`. Проверить перед покупкой.
  - Нет фоновых процессов и headless-браузера, поэтому PDF собирается в браузере посетителя.
- **Превью и MVP (этапы 1–2):** GitHub Pages, бесплатно.
  - Pages отдаёт только статичные файлы, PHP там не работает. Поэтому Laravel-сайт выгружается в статичный HTML пакетом `spatie/laravel-export`, а GitHub Actions собирает и публикует его при каждом пуше в `main`.
  - Бесплатный Pages требует публичный репозиторий. Секретов в коде нет и не будет.
  - Сайт открывается по адресу вида `<user>.github.io/<repo>/`, поэтому все ссылки и ассеты должны работать с базовым путём (через `APP_URL` / `ASSET_URL`). Позже можно подключить свой домен.
  - На Pages КП работает полностью (форма → КП → PDF), но без сохранения заявок и Telegram.
- **Язык:** только русский. Шрифты обязаны поддерживать кириллицу.
- **Данные:** собираем только название компании, город и служебные поля (дата, с какой кнопки пришёл запрос). Это не персональные данные.
- **Локальная среда разработчика (Windows):** PHP 8.3 установлен. Composer не установлен. В PHP не включены `intl`, `zip`, `pdo_sqlite`, `pdo_mysql` — Filament без них не встанет. Node 24 есть.

## 4. Подходы

| Подход | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Laravel + Filament + MySQL на reg.ru** | Сильная готовая админка на PHP: кадрирование фото, сортировка перетаскиванием, русский язык. Сайт рендерится на сервере (быстро, хорошо для SEO). Работает на дешёвом PHP-хостинге заказчика. | Компоненты watermelon (React) переносятся на Blade и Tailwind вручную. | **Выбран заказчиком** |
| Next.js + Payload CMS на VPS | Компоненты watermelon встают как есть, мощная админка. | Нужен VPS и Node-сопровождение. Заказчик хочет всё на reg.ru. | Отклонён |
| WordPress + ACF | Дешёвый хостинг, знакомая админка. | Премиальные интерактивы делать тяжело, плагины ломаются и становятся дырами в безопасности, сайт тянет к шаблону. | Отклонён |
| Tilda | Самый быстрый запуск. | Нет своей админки, КП с PDF и заявки в Telegram — на костылях, вид «как у всех». | Отклонён |

## 5. Этапы (решение заказчика)

1. **Дизайн страницы.** Сразу внутри Laravel-проекта: шаблоны Blade + Tailwind CSS v4 + лёгкий JS. Наполнение берётся из одного PHP-файла с данными (`config/content.php` или аналог), заполненного текстами из ТЗ и чернового HTML. Так на этапе 3 меняется только источник данных, а вёрстка не переделывается. Админки и базы на этом этапе нет. Просмотр — локально (`php artisan serve`) и по ссылке на GitHub Pages: статичная выгрузка публикуется автоматически.
2. **Правки дизайна** по обратной связи заказчика.
3. **Админка и запуск.** Таблицы в MySQL, разделы в Filament, перевод страниц на данные из базы, заявки на КП и уведомления в Telegram, выкладка на reg.ru. После этого сайт живёт на reg.ru, а GitHub Pages больше не нужен.

На этапах 1–2 отправка формы КП не обращается к серверу. Код формы делается так, чтобы на этапе 3 было достаточно добавить запрос к серверу без переделки.

## 6. Страница: блоки и поведение

Порядок блоков — как в ТЗ.

**Глобальные элементы**
- **Шапка:** меню-якоря по всем блокам, при прокрутке подсвечивается текущий раздел. На телефоне меню прячется в выпадающую панель.
- **Плавающая кнопка «Получить моментальное КП»** — везде, в правом нижнем углу.
- **Кнопка КП в каждом блоке** — спокойная, второстепенная по весу (не яркая плашка). Открывает ту же форму.
- **Окно cookie** — как в черновом HTML: принять / отказаться и остаться. Вариант «покинуть сайт» оставлен на усмотрение исполнителя.

**6.1 Первый экран (hero)**
- Фото на весь экран, тёмное, с бирюзово-янтарным светом. Черновые фото — `exec-*.png`; финальные будут позже.
- Текст встаёт со стороны, противоположной фигуре Андрея. На телефоне кадр обрезается так, чтобы лицо осталось в кадре.
  - На этапе 1 точка фокуса задаётся в данных.
  - На этапе 3 — в админке; там же можно загрузить отдельную вертикальную версию для телефона.
- Заголовок: «Андрей Матузов — ваш деловой партнёр в организации эффективного обучения».
- Подзаголовок: «От анализа и разработки до проведения и результата».
- С одной стороны кнопка «Получить моментальное КП», с другой — контакты (телефон, VK, Telegram, MAX).
- Подпись: персональные данные не собираем, нужны только компания и город.
- Референс по композиции: watermelon blocks/hero.

**6.2 Бегущая строка** (сразу под первым экраном)

**6.4 Направления работы** — два блока подряд.

*Обучение и спикерство*

## 7. Моментальное КП

1. **Форма во всплывающем окне.**
   - Сверху надпись: «Прочитав коммерческое предложение — вы уже на полпути к результатам».
   - Поля: «Название компании» (обязательно), «Город» (необязательно).
   - Под формой: «Телефон не нужен».
2. **После отправки** открывается персональное КП на весь экран: «для компании „…“, город, дата». Содержание и структура — по КП из чернового HTML: кто проводит, акцент работы, форматы, цены, условия, темы, достижения.
3. **PDF.** Кнопка «Скачать PDF» собирает файл в браузере. КП свёрстано отдельно под A4 (поля, разрывы страниц, светлый фон для печати), а не снимком тёмного экрана.
   - Имя файла: `КП_Матузов_<Компания>.pdf`.
   - Если генерация не сработала, используется печать браузера (`window.print`) со стилями для печати.
4. **Запись заявки (этап 3).** При отправке формы сервер сохраняет: компанию, город, дату и время, источник (с какой кнопки или блока). Андрею в Telegram приходит сообщение через бота.
   - Если Telegram недоступен, это не должно мешать посетителю получить КП.
   - Защита от спама: honeypot-поле и ограничение частоты запросов. Капча не используется, чтобы не портить «моментальность».
5. **Содержимое КП** (цены, условия, достижения, темы) на этапе 3 редактируется в админке.

## 8. Дизайн-система

- **Тема:** тёмная. Фон — почти чёрный с лёгким бирюзовым оттенком, под цвет фото.
- **Палитра заказчика:**
  - тёплый акцент — #ED9954, #F4AC5C (главный цвет КП-кнопок и выделений);
  - бирюзовый — #076465, #5CA4A7 (второстепенные акценты, свечения, ссылки);
  - песочный — #CCB494 (тонкие линии, подписи, «золото» регалий);
  - тёмно-коричневый — #52472E (поверхности и границы карточек).
  - Точные оттенки фона и текста — решение исполнителя, с обязательной проверкой контраста по WCAG AA.
- **Шрифты:** с кириллицей. Montserrat из чернового HTML не обязателен. На этапе 1 исполнитель предлагает 2 пары (заголовки + текст) на выбор заказчику. Шрифты подключаются с собственного хостинга, не с Google.
- **Движение:** спокойные появления при прокрутке, плавные раскрытия, полноэкранные окна. Всё уважает `prefers-reduced-motion`. Без тяжёлых 3D и шейдеров.
- **Качество:** вид и интерактивы выверяются по скиллам `design-taste-frontend`, `impeccable`, `ui-ux-pro-max`. Watermelon — референс по композиции и поведению, вёрстка переносится на Blade и Tailwind.
- **Адаптивность:** мобильная версия равноценна десктопной. Ширины проверки: 375, 768, 1280, 1440+.
- **Производительность:**
  - фото в WebP/AVIF с вариантами размеров и ленивой загрузкой (кроме первого экрана);
  - JS без фреймворков или с Alpine.js;
  - цель Lighthouse Performance на телефоне — 85+.
