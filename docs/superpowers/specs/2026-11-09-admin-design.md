# Админка сайта Андрея Матузова — дизайн-документ (этап 3)

Дата: 2026-11-09
Предыдущее: `docs/superpowers/specs/2026-11-06-matuzov-site-design.md` (§7 КП, §9 состав админки), этап 1 — план `docs/superpowers/plans/2026-11-06-matuzov-stage1-design.md`.

## 1. Зачем

Сейчас всё наполнение сайта лежит в PHP-файлах `resources/content/*.php`, и любую правку делает программист. Нужна удобная админка, в которой Андрей и Денис сами:
- меняют тексты;
- добавляют, удаляют, скрывают и переставляют элементы внутри существующих блоков (кейсы, события, партнёры и т. д.);
- полноценно работают с фото: загрузка пачкой, кадрирование под место на сайте, точка фокуса, порядок, замена;
- получают заявки на КП (в админке и в Telegram).

Работа в админке — **в первую очередь с компьютера**.

## 2. Цели, не-цели, анти-цели

**Цели**
- Всё, что сейчас в `resources/content/*.php`, редактируется в админке.
- Изменения появляются на matuzov.ru через несколько секунд после сохранения.
- Удобная работа с фото (§6).
- Заявки на КП приходят в Telegram и сохраняются (спецификация этапа 1, §7, п. 4).
- Выкладка кода по-прежнему автоматическая при push в `main`, по FTPS (без SSH).

**Не-цели**
- **Конструктор страниц.** Новые разделы и смена порядка разделов не нужны: структура страницы фиксированная, добавляются только элементы внутри существующих блоков.
- Роли и права: все пользователи админки равны.
- История изменений и откат версий.
- Отдельная мобильная версия админки: должна работать на телефоне, но оптимизируется под компьютер.

**Анти-цели**
- Админка позволяет испортить премиальный вид: произвольные шрифты, цвета, размеры.
- Сохранение в админке ломает публичный сайт: при ошибке пересборки сайт должен остаться в прежнем рабочем состоянии.
- Выкладка кода затирает загруженные фото, базу или `.env`.

## 3. Ограничения

- **Хостинг reg.ru, обычный (shared):** PHP, Apache за nginx, без фоновых процессов и очередей. Доступ к файлам — FTPS. SSH не используем.
  - Нужно проверить на тарифе: PHP ≥ 8.3, расширения `intl`, `zip`, `gd` (или `imagick`), `pdo_sqlite`, `fileinfo`, `mbstring`.
- **База — SQLite (один файл), без MySQL** (решение заказчика: «в прошлый раз админка работала без БД»; сервер базы не нужен, бэкап — копия файла).
- **Существующий стек:** Laravel 13, Blade + Tailwind v4 + Alpine, `App\Content\ContentRepository`, команда `site:export`, проверка `scripts/check-export.mjs`, workflow `deploy-regru.yml` (FTPS, защита от корня хостинга, метка `.matuzov-deploy`).
- **Публичный сайт остаётся статичным** (решение заказчика, вариант Б): `matuzov.ru` — папка готовых HTML.

## 4. Подходы

| Подход | Суть | Плюсы | Минусы | Решение |
|---|---|---|---|---|
| А. Живой Laravel | Сайт и админка рендерятся PHP на каждый запрос | Изменения мгновенно, проще механика | Публичный сайт зависит от PHP и базы | Отклонён заказчиком |
| **Б. Живая админка + статичный сайт** | Админка на `matuzov.ru/admin`; после сохранения пересобирает HTML-страницы сайта | Публичный сайт максимально быстрый и не зависит от базы; переиспользуем `site:export` | Задержка в несколько секунд; механика пересборки | **Выбран заказчиком** |
| В. Редактор поверх GitHub (Decap CMS) | Правки коммитятся в репозиторий, GitHub пересобирает | Бесплатно, без базы | Нет нормального кадрирования, задержка 1–2 мин | Отклонён: слаб в работе с фото |

## 5. Устройство (вариант Б)

### 5.1 Один домен: статичный сайт + админка по адресу /admin

- `www/matuzov.ru` остаётся папкой готовых HTML (как сейчас).
- Код приложения (Laravel целиком) лежит **вне веб-папки**, в `~/matuzov-app/`. В `www/matuzov.ru` кладётся маленький входной файл (например `app.php`), который запускает Laravel из `~/matuzov-app/`.
- `.htaccess` отправляет в Laravel только служебные адреса: `/admin…`, `/livewire…`, `/api/kp-lead`, `/_deploy/…`. Всё остальное отдаётся как статичные файлы. Ассеты Filament публикуются в `www/matuzov.ru` при выкладке.
- `.env`, `storage/` и файл базы `database/database.sqlite` лежат в `~/matuzov-app/` (вне веб-папки) и при выкладке не перезаписываются и не удаляются.
- Заявки КП отправляются на тот же домен — CORS не нужен.

### 5.2 Данные

- Наполнение переезжает из `resources/content/*.php` в базу SQLite (`~/matuzov-app/database/database.sqlite`).
- Появляется `DatabaseContentRepository`, реализующий тот же интерфейс `ContentRepository`. Шаблоны сайта не меняются.
- `StaticContentRepository` и файлы `resources/content/*.php` остаются: из них заполняется пустая база при первом запуске (сидер) и они используются в тестах.
- Структура таблиц — решение исполнителя. Ориентир:
  - списки (кейсы, события, партнёры, регалии, галерея, FAQ, форматы, темы с группами, мероприятия, этапы опыта, принципы) — таблицы с полями `sort` (порядок) и `is_visible` (показывать на сайте);
  - одиночные блоки (первый экран, «Об Андрее», контакты, вступление «Обучение», содержимое КП) — настройки;
  - фото — общая таблица медиа, привязанная к элементам (рекомендация: `spatie/laravel-medialibrary`).

### 5.3 Пересборка публичного сайта

- После любого сохранения, удаления, скрытия или перестановки в админке запускается пересборка: `site:export` с `APP_URL=https://matuzov.ru` в **временную папку**.
- Затем проверка (PHP-версия `check-export` или как минимум наличие обязательных страниц и отсутствие ссылок на localhost) и **публикация по файлам**:
  - каждая HTML-страница, `sitemap.xml` и `robots.txt` копируются в `www/matuzov.ru` атомарно: запись во временный файл рядом, затем переименование;
  - страницы удалённых кейсов и событий удаляются;
  - если пересборка или проверка упали, ни один файл публичного сайта не меняется, а в админке появляется уведомление «Сайт не обновлён: …».
- **Фото не копируются при каждой пересборке.** Нарезанные версии пишутся при загрузке сразу в постоянную папку `www/matuzov.ru/media/` (решение исполнителя-архитектора: подмена всей папки сайта заставляла бы копировать все фото на каждое сохранение). Ассеты (`build/`, `brand/`, иконки, `.htaccess`) обновляются в `www/matuzov.ru` при выкладке кода.
- Пересборка выполняется **после ответа браузеру** (`dispatch()->afterResponse()`), чтобы кнопка «Сохранить» не ждала. Несколько сохранений подряд объединяются: блокировка + флаг «нужна ещё одна пересборка».
- В админке виден статус: «Сайт обновлён в 14:32» или «Обновляется…», плюс кнопка «Пересобрать сайт вручную».
- Защита выкладки (метка `.matuzov-deploy`, удаление только внутри папки сайта) распространяется и на публикацию из админки: удаляются только HTML-страницы, которые пересборка сама создавала (список ведётся), а `media/` и ассеты не трогаются.

### 5.4 Заявки на КП

- Публичный сайт отправляет заявку на `https://matuzov.ru/api/kp-lead` (мета-тег `kp-endpoint`, хук уже есть в `lead-sink.js`), тот же домен.
- Сервер сохраняет: компания, город, дата и время, источник. Защита от спама: honeypot-поле и ограничение частоты (например, 5 заявок в минуту с одного IP).
- Уведомление в Telegram через бота (токен и chat id — в настройках админки). Если Telegram недоступен, заявка всё равно сохраняется, а посетитель всё равно получает КП.
- В админке: список заявок, отметка «связались», без редактирования.

### 5.5 Выкладка (GitHub → reg.ru)

- `deploy-regru.yml` перестраивается: CI собирает приложение (`composer install --no-dev`, `npm run build`) и по FTPS загружает код в `~/matuzov-app/`.
- Исключаются: `.env`, `storage/` (кроме структуры), файл базы `database/database.sqlite`, загруженные медиа.
- Защита от удаления как сейчас: стоп в корне хостинга, удаление лишнего только в папке с меткой.
- После загрузки CI вызывает **защищённую ссылку** `POST https://matuzov.ru/_deploy/{token}` (токен — секрет GitHub и `.env` на сервере). Сервер выполняет `migrate --force`, очистку и прогрев кешей и пересборку публичного сайта. Ответ — статус, который CI проверяет.
- Первичная установка (`.env`, создание файла базы, первый сидинг, создание пользователя админки) — через ту же защищённую ссылку; от Дениса — только добавить секрет токена.
- Превью на GitHub Pages отключается после запуска админки (`pages.yml` удаляется или запускается только вручную).

## 6. Админка

- **Filament** (последняя стабильная), русский интерфейс, вход по e-mail и паролю, все пользователи равны. Пользователи заводятся в разделе «Пользователи».
- **Меню:**
  - **Заявки на КП.**
  - **Контент:** Кейсы · Лента событий · Партнёры · Регалии · Галерея · Вопросы · Форматы обучения · Темы обучения (группы → карточки) · Мероприятия.
  - **Страница:** Первый экран · Бегущая строка (принципы) · Об Андрее и опыт · Контакты.
  - **КП:** цены, факторы цены, условия, темы, достижения, вступление, финальная фраза.
  - **Настройки:** Telegram, пользователи, «Закрыть сайт от поисковиков» (замена `SITE_PREVIEW`).
- **Для всех списков:** добавить; удалить (с подтверждением); скрыть, не удаляя; порядок перетаскиванием; кнопка «Посмотреть на сайте».
- **Тексты:**
  - короткие поля — простой текст;
  - длинные поля — текст с переносами строк;
  - поля «Об Андрее» (абзацы), ответы FAQ, запрос, план, результат и отзыв кейса, описание события — минимальное оформление: жирный, курсив, ссылка, список. Без шрифтов, цветов и размеров. На сайте HTML очищается (whitelist тегов).
  - План кейса — список шагов (повторяемое поле) вместо строки с «→».

### 6.1 Фото

- **Загрузка:** перетаскиванием, несколько файлов сразу (галерея, события — пачкой до 30). Форматы JPG, PNG, WebP, HEIC (если хостинг умеет). До 15 МБ на файл.
- **Обработка:** при сохранении фото нарезаются в webp и avif нужных ширин (как `scripts/images.mjs` сейчас, но на сервере средствами PHP: GD или Imagick). Если avif на хостинге недоступен — только webp; `<x-picture>` должен это переживать.
- **Кадрирование под место** (редактор открывается с нужной рамкой; двигать, масштабировать, повернуть, отразить):

  | Место | Пропорция |
  |---|---|
  | Первый экран | 16:9 + точка фокуса; отдельное вертикальное фото для телефона 9:16 (необязательно) |
  | «Об Андрее» | 4:5 |
  | Этапы опыта | 16:10 |
  | Карточка и обложка кейса | 16:10 (обложка кадрируется по точке фокуса) |
  | Фото кейса | 4:3 |
  | Событие | 1:1 (превью) и 4:3 (в окне) — одна загрузка, превью по центру или точке фокуса |
  | Галерея | свободная пропорция |
  | Регалия | 16:10 |
  | Партнёр | без кадрирования, логотип целиком (PNG/SVG с прозрачностью) |

- **Список фото:** порядок перетаскиванием, замена без потери подписи, удаление; у каждого фото подпись и alt.
- **Оригинал** хранится, кадрирование можно переделать.

## 7. Что не меняется

- Внешний вид и вёрстка публичного сайта, эффекты (стекло, КП «из принтера», раскрытие кейса).
- Тесты этапа 1 продолжают работать на `StaticContentRepository`.

## 8. Решения, оставленные исполнителю

- Схема таблиц и связей, медиабиблиотека, плагины Filament (сортировка, редактор фото, точка фокуса).
- Имя входного файла Laravel в `www/matuzov.ru` и точные правила `.htaccess`.
- Механизм блокировки и объединения пересборок.
- Проверка выгрузки на сервере (PHP-аналог `check-export`).

## 9. Риски

- Возможности хостинга (версия PHP, расширения, лимиты памяти и времени выполнения при пересборке и нарезке фото): проверить в первую очередь.
- Пересборка при большом числе фото: нарезка — при загрузке фото, а не при пересборке; пересборка только рендерит HTML и копирует готовые файлы.

## 10. Открытые вопросы (не блокируют начало)

- Тариф reg.ru: версия PHP и расширения (`pdo_sqlite`, `intl`, `gd`), лимиты памяти и времени.
- Telegram: бот и chat id Андрея.
- Кто и с какими e-mail будут пользователями админки.
